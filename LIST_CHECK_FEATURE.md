# 📋 Проверка списков

Билет «По списку» дешевле, поэтому он выдаётся только тому, кто выполнил условия LEMON:

1. Подписан на LEMON в **Telegram** и во **ВКонтакте** (обязательно).
2. Плюс **оба**: отметил **3 друзей** в комментарии под постом мероприятия в ВК **и** выложил **сторис** с отметкой LEMON (скриншот). Если у события нет поста ВК, требуется только сторис. Переменная `LIST_REQUIRE_BOTH=0` возвращает режим «достаточно одного из двух».

Всё проверяется автоматически. Админ получает только сомнительные скриншоты и выборочный аудит.

## Как это работает

| Условие | Как проверяется |
|---|---|
| Подписка на ТГ | `getChatMember` по каналу (бот — админ канала). Проверяется при покупке и на входе |
| Привязка ВК | Человек отправляет одноразовый код `LEMON-XXXXXX` в личку сообщества ВК. Бот получает id отправителя, подменить его нельзя. Один ВК — один Telegram |
| Подписка на ВК | `groups.isMember` по привязанному id. При покупке и на входе |
| 3 друга в ВК | Слушатель событий сообщества (Long Poll) видит комментарии под постом мероприятия, считает живые отметки (разные люди, не сам автор, без автоотметки при ответе, без удалённых страниц). Удаление или правка комментария снимает зачёт |
| Сторис | Скриншот → ИИ (Gemini или Claude) проверяет: это сторис, есть отметка LEMON, видна публикация, имя автора совпадает с привязанным профилем ВК. Дубли отсекаются по хешу. Уверенно «да» → принято, уверенно «нет» → отказ, остальное → админу |

## Защита от убытков

- **Квота «По списку»** на каждое мероприятие. Максимальные потери = квота × разница цен (бот показывает её при создании события).
- **Один билет «По списку» на человека** на мероприятие.
- **Перепроверка на входе:** при скане QR бот снова проверяет подписки и условие. Если что-то не выполнено, он пишет **«ДОПЛАТА X₽»** (разница между ценой «Без списка» и оплаченной). Это закрывает схему «подписался → купил → отписался».
- **Выборочный аудит:** часть авто-одобренных сторис уходит админу (`STORY_AUDIT_PERCENT`). «🚫 Снять со списков» навсегда закрывает человеку доступ к спискам.
- **Лимит попыток** со скриншотами (`STORY_MAX_ATTEMPTS`).
- Покупку нельзя обойти кнопкой подтверждения: условия проверяются и при выдаче билета.

Что система не ловит: подделанный скриншот, который ИИ принял, и «друзья» из фейковых аккаунтов. Для этого есть квота, аудит и доплата на входе.

## Настройка

### 1. Telegram
Сделайте бота **администратором канала LEMON** (иначе Telegram не отдаёт список подписчиков).

### 2. ВКонтакте (сообщество LEMON)
1. **Управление → Сообщения:** включить сообщения сообщества.
2. **Управление → Работа с API → Ключи доступа:** создать ключ сообщества с правами на сообщения и управление.
3. **Управление → Работа с API → Long Poll API:** включить; версия API — актуальная (5.199); в типах событий отметить:
   - «Входящее сообщение»
   - «Добавление комментария на стене», «Редактирование комментария на стене», «Удаление комментария на стене»
4. Скопировать токен в `VK_TOKEN`, числовой id сообщества в `VK_GROUP_ID`.

### 3. Переменные окружения
См. `.env.example`. Для проверки скриншотов нужен ключ `GEMINI_API_KEY` (или `ANTHROPIC_API_KEY` при `AI_PROVIDER=anthropic`).

### 4. Диагностика
Админ отправляет боту `/listcheck`. Он показывает, всё ли настроено: канал ТГ и права бота, токен ВК, `groups.isMember`, Long Poll, запущен ли слушатель, какой ИИ подключён.

### 5. Включение
Поставьте `LIST_VERIFICATION=1` и перезапустите бота. Пока флаг выключен, бот работает как раньше.

При создании события появятся два новых шага: **ссылка на пост в сообществе ВК** (под ним гости отмечают друзей; пост должен быть на стене сообщества LEMON) и **квота «По списку»**. Для уже созданных событий задайте их в «📋 Управление» → «👥 Пост ВК» и «📋 Квота по списку».

## Для гостя

«📋 По списку» → экран условий с галочками:
подписка ТГ → «🔗 Привязать ВК» (отправить код сообществу) → подписка ВК → друзья в комментарии (бот увидит сам) и «📸 Отправить скриншот сторис». Затем «🔄 Проверить» → «🎟 Купить по списку».

## Что важно знать

- Билеты «По списку», выданные **до** включения проверки, на входе не перепроверяются (нет данных); их, как и раньше, нужно сверять по списку вручную.
- Состояния диалогов хранятся в памяти: после перезапуска бота гость, который как раз отправлял скриншот, нажимает кнопку заново. Привязки ВК, комментарии и решения хранятся в базе и не теряются.
- Пока слушатель ВК не запущен (ошибка токена, Long Poll выключен), привязка и учёт комментариев не работают; `/listcheck` это покажет. Комментарии, оставленные в это время, не учтутся.
- Если ТГ или ВК недоступны при покупке, билет «По списку» не выдаётся (покупка закрыта до восстановления). На входе, наоборот, гостя не блокируют, а просят сверить вручную.

## Миграция со старой версии проверки списков

Эта версия **заменяет** прежнюю реализацию (проверка только сторис через Gemini без привязки к покупке):

- Удалены `handlers/list_check_handlers.py`, `utils/vk_api.py`, `utils/gemini_vision.py`, `utils/image_hash.py`, а также лог `error.txt` (логи в репозитории не нужны). Из `requirements.txt` убраны `google-generativeai` и `requests`.
- Кнопка меню **«📋 Проверить список»** осталась: она открывает выбор мероприятия и экран условий (кнопка видна, когда `LIST_VERIFICATION=1`).
- Посты ВК, привязанные к событиям по-старому (таблица `events_vk`), при старте **автоматически переносятся** в новые поля события, если ссылка вида `wall-123_456`. Для них проверьте, что пост на стене сообщества LEMON.
- Старые таблицы (`user_vk_links`, `events_vk`, `list_checks`, `screenshot_hashes`) бот больше не использует; их можно оставить или удалить вручную. Привязку ВК по старой схеме (имя, введённое руками) переносить не нужно: гости привязывают ВК заново кодом.
- Старые переменные `VK_API_TOKEN` и `VK_COMMUNITY_ID` заменены на `VK_TOKEN` и `VK_GROUP_ID`.
- `handlers/payment_handlers.py` и `utils/payment.py` (заготовка оплаты) я не трогал: они нигде не подключены.
- Добавлены `.gitignore` и `.env.example`. Если папки `__pycache__` уже попали в репозиторий: `git rm -r --cached __pycache__ */__pycache__`.
